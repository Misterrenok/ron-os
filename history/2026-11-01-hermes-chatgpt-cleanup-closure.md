## Решение Рона и канонические правила

- **Прямое постоянное требование Рона:** после **каждой** задачи ChatGPT и Hermes самостоятельно удаляют свои ненужные временные файлы, кэши, скрипты, тестовые среды и заканчивают неиспользуемые процессы/сессии; проверяют, что остатка нет. Сохраняют рабочие сервисы, авторизацию, пользовательские файлы, нужные результаты и резервные копии. Блокер указывается явно; «нет прямого инструмента» не доказывает невозможность альтернативного пути и не означает DONE.
- Владелец требования: `PERSON.md`, правило от 2026-11-01, включено через [PR #218](https://github.com/Misterrenok/ron-os/pull/218) (с проверкой `continuity`). Штатная процедура уже установлена в `PROTOCOL.md` → «Execution and writes», `skills/ron-work-protocol.md` → closeout, а автономный тест — `tests/resource_lifecycle_guard.py`. Повторять правило в дополнительных скиллах без нового проверяемого поведения не нужно.
- В Hermes правило добавлено и прочитано обратно в **обоих** `SOUL.md`: основной профиль и `roncompanion`. Эти два файла являются реальными пользовательскими инструкциями профилей; отдельные изменения в них **не** означают, что внешние агенты гарантированно будут соблюдать правило. ## Урок: удаление собственного GitHub-ресурса

- После успешного merge PR #218 ChatGPT **ошибочно оставил** временную ветку `preference-cleanup-20261101` и несколько раз заявлял, что ему нечего делать, ссылаясь на отсутствие прямого delete-branch метода. Пользователь прямо отверг такой статус. **Это был незакрытый долг ассистента, не действие для Рона.**
- Проверен альтернативный исполнитель: веточно-ограниченный одноразовый GitHub Actions workflow, создаваемый **только в уже слитой временной ветке**, `permissions: contents: write`, `push` trigger на **точную** ветку, self-delete через `DELETE /repos/.../git/refs/heads/<exact-branch>` с встроенным GitHub Actions token. Предварительно проверять, что PR действительно merged, ветка не `main`, endpoint и authority конкретны; workflow не вносить в main.
- Практическое подтверждение: GitHub Actions run **41277979179** = success; после него точный ref возвратил **404**, поиск ветку не нашёл, workflow-файл отсутствует на `main`; PR #218 оставался merged, guard CI success. Это **завершило** случай; не создавать следующий ресурс без проверенного жизненного цикла.
- **Общий критерий:** отсутствие удобного инструмента запускает поиск другого уже разрешённого и проверяемого пути, а не автоматическую передачу работы человеку. Процесс / скрипт / временная ветка закрываются только после независимой проверки целевого отсутствия. Это operational lesson и historical evidence; runtime-protocol и независимый guard уже содержат правило, поэтому не раздувать их дублирующими мантрами.
