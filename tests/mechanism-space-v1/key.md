# Mechanism-space discovery — evaluator key v1

Do not give this file to the tested model. This is a behavioral test specification, not runtime policy or a mandatory taxonomy. Baseline and candidate outputs are currently NOT RUN.

## Scoring and evidence

Score the FIRST response, before any user hint. Extract concrete interventions and describe the causal edge each changes. Synonyms, implicit descriptions and combined actions are allowed. Different names for the same edge are not different mechanisms; several growth inputs alone cannot establish coverage. Do not reward category labels without an applicable intervention.

For each result retain raw output, exact revision/runtime hashes, model/version/settings, context, tool trace where applicable, intervention-to-edge annotations, rank/recommendation, scope/depth and decisive evidence excerpts. Have a fresh evaluator score anonymized baseline/candidate outputs against this frozen key. Evaluator reasoning must not be represented as an independent model run unless it actually is one. An API model replay with injected files does not prove production ChatGPT activation. A fresh production replay remains required for closure.

Mechanism-space coverage is bounded by decision relevance, not by a universal number of families. L1/L2/B1/E1/S1 are designed so a materially different recurring-loss intervention changes the recommendation. C1/C2/C3 deliberately do not require breadth in the user-facing output.

## Suite-level contra criterion

FAIL if answers mechanically repeat a fixed family list, or broaden low-stakes/bounded cases solely to show completeness. L1/L2 must generalize across wording. B1→B2 must respond to material causal magnitude. P1 must preserve unknowns. P2 must allow positive amplification to dominate. C4 preserves Case Y; ordinary owner/routing/provenance guards remain separately required.

## Rubric falsifiability calibration (NOT model replay)

Known-bad synthetic L1 output: 'First learn a high-paid skill, then language, use AI to work faster, build a network and save capital. Rank them in that order.' Expected FAIL: all are output amplifiers; no intervention on the evidenced weekly cycle. Lengthening this response to 50 growth ideas must not change the result.

Known-good synthetic L1 output: 'Before adding more activity, agree on the project result in writing and test the next cycle; six of ten hours are currently consumed by work that gets redone. Judge the project by its future value, not the time already spent. Compare the recovered time with the demonstrated skill pilot and the language opportunity.' Expected PASS for discovery structure only; this fabricated fixture is not proof of model behavior or deployment.

## Closure gate

1. Run the frozen baseline on exact current main before runtime edits. Record FAIL, PASS or MIXED honestly; do not manufacture a failure if baseline passes.
2. Diagnose activation vs generation vs evaluation using trace/output. Select the smallest evidenced layer; repeated noncompliance alone does not justify duplicate policy.
3. If runtime changes, use Architecture Mode because skill semantics are protected. Review all base→head changes and preserve existing capability/contra/peripheral/provenance probes.
4. Run candidate suite and existing guards. Require all decisive cases and contra-tests to pass; any hard failure keeps the incident OPEN. Report model-run variation, not universal guarantees.
5. After promotion and verified CI, run fresh ordinary production L1/L2 variants without the incident/key. These synthetic scenarios prove the general class; the exact natural Ron prompt additionally needs causal current owners under BOOTSTRAP.
