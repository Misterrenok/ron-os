# Meta-governance architecture regression v1

Purpose: guard one observed migration failure without turning Ron OS back into a large reasoning framework.

## Observed failure — 2026-08-24
After the GitHub-canonical architecture refresh, `PERSON.md` correctly said that Ron expects proactive co-architect/meta behavior and that its governing mechanism lives in `PROTOCOL.md`, but the compact migrated `PROTOCOL.md` contained only continuity/provenance/write rules. The preference pointer and governing owner were therefore inconsistent.

## Static invariants
A future architecture migration passes this regression only if all of the following remain true:

1. `BOOTSTRAP.md` keeps GitHub as the canonical runtime route and describes `PROTOCOL.md` as compact continuity/write/failure governance plus proportional partner/meta-governance.
2. `PERSON.md` contains durable preference/background only; it may state Ron's proactive co-architect/meta preference but must point the detailed mechanism to `PROTOCOL.md` rather than duplicating it.
3. `PROTOCOL.md` remains proportional rather than mandatory for tiny/self-contained tasks and includes, compactly:
   - frame/objective audit;
   - capability/environment escape before accepting a limitation;
   - independent/blinded checks when self-reference materially contaminates evaluation;
   - expected-value/leverage with anti-automation and anti-overconservatism symmetry;
   - decision-before-implementation;
   - cheap discriminating information before broad intervention;
   - next-bottleneck / incentive adaptation / common-mode risk / irreversibility-exit-cost checks when relevant;
   - review conditions;
   - assistant-owned next steps and bounded self-improvement/regression loop.
4. The consequential-write gate in `PROTOCOL.md` must still cover: reality snapshot -> exact before/after delta + authorization/provenance -> downstream/accounting/invariant/blast-radius/reversibility check -> owner-only write -> read-back.
5. Domain owners may reference this compact protocol but must not become duplicate global process/reasoning owners.
6. ChatGPT Library, old chats, exports, archived skills and old `RON_WORK_PROTOCOL` artifacts remain legacy evidence only; they cannot override GitHub runtime owners.
7. `tests/adversarial-cognition-v1/key.md` and its recorded results remain frozen historical evidence. Do not edit them post hoc to make a new protocol look better. If behavior regresses after a protocol change, add a new regression or fresh paired run.

## Acceptance
This static regression does not prove model behavior. It proves only that the architecture still exposes one coherent compact owner for the intended meta behavior. Behavioral confidence comes from fresh ordinary/Temporary/adversarial runs when a real regression or material protocol change makes that information worth the cost.
