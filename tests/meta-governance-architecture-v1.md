# Meta-governance architecture regression v1

Purpose: guard observed migration failures without turning Ron OS back into a large reasoning framework.

## Observed failures — 2026-08-23/24
1. After the GitHub-canonical architecture refresh, `PERSON.md` correctly said that Ron expects proactive co-architect/meta behavior and that its governing mechanism lives in `PROTOCOL.md`, but the compact migrated `PROTOCOL.md` contained only continuity/provenance/write rules. The preference pointer and governing owner were therefore inconsistent.
2. Earlier Ron OS iterations repeatedly overinterpreted static/package/file correctness as proof that fresh ordinary-chat runtime retrieval worked; the actual end-to-end user path failed until explicitly tested.
3. A long remediation-heavy chat became a reliability risk, but the assistant noticed the need for a clean continuation too late instead of proactively checkpointing and handing off.
4. The compact migration dropped several durable process semantics that existed in the older working system: transferable-generalization instead of exact-trigger patching; derived-view ownership/propagation discipline; baseline/coupled-change attribution integrity; and ordinary-chat vs scarce Work/Codex routing.
5. A deeper pass found additional accepted reasoning lessons that had not survived compaction explicitly enough: confirmed reality must correct the stored model rather than be bent to stale bookkeeping; disconfirming evidence/competing hypotheses must be considered when they can change a consequential decision; when an external root source is not practically controllable, own-side mitigation should carry the plan while cheap influence runs in parallel; recurring outputs with no demonstrated consumer should face a deletion test before optimization; nonzero changes must propagate through accounting/invariants rather than disappearing locally; incentive/redundancy/irreversibility analysis must include already-created distortion plus recovery/switching/reversal cost; and a systemic fix must still close the present concrete actionable gap.
6. Live executors survived the storage migration with stale routing: an active TickTick system-index still named Library-era owners, and the active architecture-audit automation still bootstrapped from Library `RON_WORK_PROTOCOL.md`/`RON_HANDOFF.md` after GitHub had become canonical.
7. XMind was a validated live goal-map integration on 2026-08-23, but the initial compact GitHub routing omitted it entirely while an active weekly TickTick review still targeted that map. The correct contract is dual-level: live XMind owns the exact structure/content of the map artifact itself; measurements/current facts/policy copied into that map remain downstream projections of their upstream owners and cannot override them. If live XMind is unavailable, exact current map contents are `UNVERIFIED` rather than reconstructed from archived snapshots.
8. Hygiene/compaction removed mutable project material from legacy surfaces without always creating a replacement owner. This could make a correctly cleaned Ron OS unable to recover real active work. The concrete 2026-08-24 example was the Trendyol Tampermonkey printing project: a confirmed working rollback baseline and explicit next step existed in chat, but no GitHub project owner could recover them until the deep migration pass created `projects/trendyol-print-automation.md`.
9. A second continuity gap appeared in mobility/legal-strategy state: the pre-hygiene snapshot contained a live Türkiye residence-status conflict plus an unresolved Germany/Ausbildung route decision, but PERSON compaction intentionally removed mutable/legal state without a replacement owner. `domains/mobility.md` now preserves only the last-confirmed conflict/strategy fallback and requires current official/live verification for consequential status/legal claims.
10. Ron had supplied Anthropic `system-prompts.md` on 2026-08-18 and a fresh-chat audit accepted a narrow Ron-specific subset as nonduplicating working rules. Later compaction preserved some of their effect but dropped several explicit semantics: completion discipline, current-turn constraint anchoring, decisive recommendation, epistemic restraint about people, and provenance distinctions such as raw transcript/source over summary, general positive reaction not silently approving assistant-added details, and one mention not becoming a durable user fact/preference. The source document itself remains legacy evidence; only the accepted transferable subset belongs in `PROTOCOL.md`.
11. The 2026-08-23 partner/compass upgrade had also been partially flattened during compaction: blind-spot/global-agenda comparison and truth-preserving behavioral influence were not explicit enough to survive future migrations. They were restored proportionally: high-cost/important work may be redirected to a clearly better open priority, while cheap self-contained requests are not hijacked; behavioral design is allowed, deception/fabricated evidence is not.
12. A durable external strategic framework was lost from `PERSON.md`: Ron had explicitly adopted Naval Ravikant / “How to Get Rich” as a long-term decision filter (wealth/assets over status/time-only income; ownership/equity/IP; specific knowledge; build+sell; permissionless leverage; accountability/judgment; long-term trusted games; compounding; uniqueness/freedom). It belongs in durable personal strategy context, not `PROTOCOL.md`, and should not disappear silently during hygiene.

## Static invariants
A future architecture migration passes this regression only if all of the following remain true:

1. `BOOTSTRAP.md` keeps GitHub as the canonical runtime route and describes `PROTOCOL.md` as compact continuity/write/failure governance plus proportional partner/meta-governance.
2. `PERSON.md` contains durable preference/background only; it may state Ron's proactive co-architect/meta preference but must point the detailed mechanism to `PROTOCOL.md` rather than duplicating it. Explicitly adopted durable strategic frameworks must be preserved there (or explicitly superseded by Ron), not silently dropped during hygiene; they remain preferences/filters rather than global runtime authority.
3. `PROTOCOL.md` remains proportional rather than mandatory for tiny/self-contained tasks and includes, compactly:
   - frame/objective audit;
   - proportional blind-spot/global-compass scan for meaningful time/money/attention/option-cost commitments;
   - disconfirming evidence / materially competing hypotheses when decision-relevant;
   - capability/environment escape before accepting a limitation;
   - control-surface-first handling when the root source is outside practical control;
   - resource-aware tool routing: ordinary-chat tools first when sufficient, scarce/heavier Work/Codex/computer-use only when materially justified, Ron manual work only as irreducible input;
   - independent/blinded checks when self-reference materially contaminates evaluation;
   - epistemic separation of verified evidence, assumptions/models, conclusions and `UNKNOWN` when consequential;
   - current-turn constraint anchoring + completion/retry discipline for multi-part or off-target work;
   - one best-supported recommendation first when Ron asks what to choose/do, with alternatives only for material trade-offs;
   - truth-preserving influence: defaults/friction/reminders/framing may help behavior, but no fabricated facts/evidence/diagnoses/outcomes/false certainty;
   - no unsupported motive/diagnosis/mental-state attribution to people;
   - expected-value/leverage with anti-automation and anti-overconservatism symmetry;
   - deletion-before-optimization for recurring outputs/processes with no demonstrated consumer/action;
   - highest-useful transferable generalization rather than exact-trigger process patches;
   - decision-before-implementation;
   - cheap discriminating information before broad intervention;
   - conservation/accounting/invariant propagation for nonzero system changes;
   - baseline/experiment and coupled-change attribution integrity;
   - next-bottleneck / incentive adaptation plus repair of created distortions / downtime-recovery-switching-common-mode risk / irreversibility-exit-reversal-cost checks when relevant;
   - review conditions;
   - assistant-owned next steps, concrete-gap closure after systemic fixes, and bounded self-improvement/regression loop;
   - explicit distinction between static/storage correctness and real end-to-end production-path validation before material PASS claims;
   - proactive checkpoint/handoff when the active chat itself becomes a material context-reliability risk.
4. The authority/provenance layer must distinguish Ron's explicit report/decision, assistant proposal, inference/hypothesis, external fact and stored summary where confusion matters; raw source/transcript beats a conflicting summary, positive reaction does not silently approve assistant-added details, and a single mention is insufficient to promote a durable fact/preference.
5. The execution layer must preserve `reality > stale representation`: planned/prefilled/projected/app-entered state is not real-world execution, and confirmed execution that conflicts with a stored model/projection requires correcting/invalidating the representation rather than forcing reality to fit it.
6. The authority layer must preserve a derived-view contract: a projection/analytics surface cannot introduce unique upstream policy or outrank its owner; conflict means stale projection, owner-first repair, then propagation/read-back or retirement.
7. The consequential-write gate in `PROTOCOL.md` must still cover: reality snapshot -> exact before/after delta + authorization/provenance -> downstream/accounting/invariant/blast-radius/recovery-switching/reversibility check -> owner-only write -> read-back + materially used projection propagation/retirement.
8. **Hygiene/migration gate:** before deleting or neutralizing continuity-relevant mutable/project state from PERSON/memory/Library/handoffs/legacy artifacts, identify/create the correct replacement owner and transfer the smallest current residue with provenance/AS_OF, or explicitly retire it. A cleanup that destroys the only recoverable active-project or unresolved cross-domain state is a regression even if every remaining file is architecturally clean.
9. Domain/project owners may reference this compact protocol but must not become duplicate global process/reasoning owners. Project files should hold only state needed to resume that project; exact mutable external state still belongs to its live owner where available.
10. Active external executors/projections that materially guide behavior (e.g. TickTick index cards, scheduled Ron OS audits, weekly retros) must route to the current GitHub bootstrap/owners, not merely coexist with correct GitHub files. Migration validation must inspect these live surfaces, not only repository contents.
11. Integration ownership must be typed rather than flattened. Neon remains derived integration/analytics relative to upstream owners. Live XMind owns its own exact map artifact, while facts/measurements/policy copied into that map remain downstream projections. If a live integration is unavailable, exact current contents are `UNVERIFIED`, not reconstructed from archived snapshots.
12. Active domain/project routing must be discoverable from `BOOTSTRAP.md`/`CURRENT.md` when a new chat needs continuation. As of this regression, e-commerce routes to `domains/ecommerce.md`, mobility/residence/Germany strategy routes to `domains/mobility.md`, and Trendyol print automation routes to `projects/trendyol-print-automation.md`; future replacements may change paths, but the continuity function must remain. Mobility/legal owners must distinguish last-confirmed user state from current legal/government facts and require official/live re-verification where consequential.
13. Anthropic `system-prompts.md` and similar third-party prompt archives remain source/evidence only, never runtime authority. Do not copy another product's safety/product/system layer wholesale into Ron OS; preserve only explicitly accepted, nonconflicting, transferable Ron-specific working rules whose function is still useful under OpenAI system/developer constraints.
14. ChatGPT Library, old chats, exports, archived skills and old `RON_WORK_PROTOCOL` artifacts remain legacy evidence only; they cannot override GitHub runtime owners.
15. `tests/adversarial-cognition-v1/key.md` and its recorded results remain frozen historical evidence. Do not edit them post hoc to make a new protocol look better. If behavior regresses after a protocol change, add a new regression or fresh paired run.

## Acceptance
This static regression does not prove model behavior or external-executor alignment. It proves that the architecture exposes one coherent compact owner for the intended meta behavior and records the known migration traps. Behavioral/runtime confidence requires fresh ordinary/Temporary/adversarial/end-to-end checks and live-surface read-back when a real regression or material protocol/runtime change makes that information worth the cost.
