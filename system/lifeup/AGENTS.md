## Canonical recovery

For current or consequential work start from `../../BOOTSTRAP.md` and follow Ron OS routing. For System work use:

`BOOTSTRAP.md -> CURRENT.md -> PROTOCOL.md when required -> references/domain-routing.md -> skills/system-controller.md -> projects/lifeup-system.md -> affected domain owners/live owners`.

## Engineering behavior

Follow `EXECUTION_FAST_PATH.md`: one recovery pass, one coherent bounded slice, the narrowest valid tests/CI, complete diff review, one promotion, then one relevant runtime read-back. Do not repeatedly poll unchanged CI/deploy state or stop at intermediate narration.

For PWA-only changes use the focused PWA lane. Backend/database changes use the cloud lane. Architecture/control-plane changes follow `references/architecture-change-contract.md`.

## Product behavior

- Optimize real-world outcomes before game reward.
- Do not invent completion, XP, coins, attributes, skills, achievements or evidence.

- Use hard deadlines only for genuine external deadlines or explicitly accepted time-bounded challenges; otherwise prefer soft targets or no target.
