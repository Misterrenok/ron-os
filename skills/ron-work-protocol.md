# Skill — Ron work protocol

Scope: every personal, project, current or continuing request for Ron, including broad or short prompts such as “improve nutrition”, “gain muscle”, “need money” or “how to earn”.

1. Start from `BOOTSTRAP.md` -> `CURRENT.md`.
2. For nontrivial reasoning, read `PROTOCOL.md`.
3. Route through `references/domain-routing.md`; infer the primary domain and automatically load the smallest causally complete union of supporting domain skills, exact owners and claim-relevant live owners. Ron never has to name skills or request continuity capture.
4. Before concluding, define the real desired outcome and shortest complete lifecycle that can change success. Run an internal adaptive scan across Ron's goals/values/constraints; owners/live measurements/execution; current authoritative evidence; time/money/availability/tools/logistics; preparation/use/storage/transport/maintenance/cleanup; taste/usability/adherence; safety/interactions/failure modes; and short/long-term/second-order effects.
5. Deepen research and tool use whenever a factor's plausible range can change the choice, ranking, safety, cost, feasibility or next step. For consequential health/legal/financial or irreversible decisions, prefer current official/primary sources and systematic reviews/meta-analyses where appropriate; use primary studies when they can materially update the synthesis. Compare a strong alternative and test sensitivity to key unknowns before stopping. Before the final answer, re-read the exact owner/source for every material number, date, ID, active status, unit and timezone; never transcribe exact claims from intermediate memory. Model-proposed prices, quotas, thresholds or pilot sizes without a direct source must be labeled estimates/start hypotheses with a calibration condition.
6. Recover missing data yourself from Ron OS, the exact owner, live app or a safe alternative source. If a decision-critical source remains unavailable, either proceed with a safe reversible option marked `UNKNOWN` or ask Ron only for the minimum user-only data/connection that materially changes the decision. Do not turn Ron into the collector of nice-to-have inputs.
7. Give one concise outcome-first pragmatic answer. Optimize truth, safety, health/longevity, total expected value, money, time, autonomy, reversibility, adherence and downside across short and long horizons, while respecting Ron's explicit values. Do not dump the internal factor matrix unless it helps the decision; breadth of analysis is not itself quality.
8. Before finishing every continuity-relevant task, read the affected owners; remove/replace superseded runtime data; record all deltas, where work stopped, OPEN/CLOSED/CONFLICT/UNKNOWN, blockers and next step in their exact owners; then read back. Do not create a fake log entry when nothing changed and no continuation point exists.
9. Mutable state must not remain in skills or native memory. Move current truth to the exact owner and remove stale copies; Git history or an explicit archive may retain provenance but cannot act as runtime.
10. Ron grants standing authorization for Ron OS continuity-capture without a separate prompt. This does not authorize unrelated purchases, payments, messages, publications, deletions or live-system side effects.
11. Synthesize one answer/action across selected domains, distribute each material delta to its own owner, and update `CURRENT.md` only as a short material cross-domain index.
12. For migration/compaction/continuity defects, read `references/continuity-contract.md`; for authority/routing/owner/snapshot/write-gate architecture changes also enter `references/architecture-change-contract.md` and use its candidate/preservation/promotion gate. Run the relevant executable guards before closeout.

This skill owns procedure only, never mutable personal/project state.
