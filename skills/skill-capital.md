# Skill — skill capital

Scope: choose, build, prove and compound capabilities whose value persists across roles or materially advances Ron's current strategic direction. This is a portfolio/optimization layer, not a replacement for concrete learning systems.

## Runtime route
- Read `domains/skill-capital.md` first for current portfolio state.
- Add `domains/learning.md` + `skills/ron-learning.md` when actual study/practice design or observed learning progress matters.
- Add mobility, e-commerce, finance, schedule, health or XMind only when they materially change skill value, feasibility, target-market relevance or time/cost.
- Current labor-market demand, credential rules and tool/technology state require current external/live evidence; never freeze them here.
- Actual studied/practiced/applied work is owned by Ron's direct execution report or the relevant live app/source, not by a plan.

## Skill-capital loop
1. **Target:** recover the current horizon/outcome first; do not optimize a skill in a vacuum.
2. **Candidate pool:** identify plausible skills from bottlenecks, prerequisite chains, market/opportunity evidence and complementary skills already owned.
3. **Rank:** compare strategic relevance, transferability, durability, demand/leverage, time-to-useful-value, proofability, complementarity/optionality, automation/substitution risk, cost/time and downside. Use ranges/qualitative confidence when evidence is weak rather than fake precision.
4. **WIP limit:** default to one primary build skill at a time unless there is a concrete reason to parallelize; maintenance of already-built skills may continue separately.
5. **Build:** baseline -> weakest/highest-leverage subskill -> deliberate practice/application -> fast feedback/error correction -> repetition under increasing difficulty.
6. **Prove:** convert competence into evidence appropriate to the domain: shipped artifact, before/after result, assessment, portfolio item, case, credential when it opens a real gate, or observed performance.
7. **Compound:** prefer skills that reinforce existing assets, unlock later skills/opportunities or remain useful across multiple plausible futures.
8. **Review:** while a primary skill is active, reassess at least monthly or at a material milestone/change in target evidence; continue, narrow, replace or retire explicitly.

## Decision rule
A credential is neither automatically valuable nor automatically useless. Prefer **real capability + evidence of capability + credential/signal only when the target market or gate rewards it**.

## Boundaries
- Do not swallow ordinary education/language execution; learning owns that procedure/state.
- Do not create a new course/certification habit because it is easy to count. The output must be improved capability or a real access signal.
- Do not silently select an active skill from stale memory or old plans. If current owners/evidence do not establish the ranking, keep it `UNKNOWN` until evaluated.
- No Calendar/TickTick/course purchase, enrollment or other live mutation is authorized merely because this skill recommends it.

This skill owns procedure only, never mutable portfolio state.
